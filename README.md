# Plan for myself

https://plan-for-myself.vercel.app

> 매일 실패한 것을 기록하고, 그 실패를 성공으로 바꿔 나가고 싶었습니다.

### 제공되는 기능

1. **달력** — 매일 공부시간과 실패한 것을 기록합니다
2. **통계** — 어떤 실패를 반복하고, 어떤 실패를 줄였는지 지난달과 비교해 보여 줍니다

이를 통해, 같은 실패를 반복하지 않도록 유도하고자 합니다.

## AI 활용

작업 계획·기획·디자인·개발·QA, 모든 단계에 AI를 사용했습니다.

### 작업 계획

AI와 함께 서비스를 다시 만들어 공개하기까지의 일을 단계로 나누고, 순서를 정했습니다.

- **상위 로드맵 작성** — 1. 기획 → 2. 디자인 → … → 6. 페이지 개발 → … → 12. 출시 전 총점검 → 13. 공개의 13단계로 나눴습니다
- **하위 로드맵 구체화** — 단계마다 하위 작업을 분리했습니다. 예를 들어 6. 페이지 개발은 6.0 화면 마크업, 6.1 사용자 식별과 권한 검사, 6.2 달력과 기록 폼, 6.3 통계 … 로 나눴습니다
- **직렬·병렬 배치** — 서로 기다릴 필요가 없는 작업은 나란히 돌렸습니다. 예를 들어 API·DB와 화면 마크업을 나란히 만들고, 기능은 그 뒤에 붙였습니다.

### 디자인

디자이너의 역할을 저와 AI가 직접 수행했습니다.

- **문구 다듬기** — 버튼·안내 문구를, 처음 읽은 사람이 무엇을 예상할지를 기준으로 고쳤습니다
- **직관적인 UI/UX** — 정보를 주지 않은 AI가 브라우저로 사이트를 직접 써 보며, 화면만 보고도 무엇을 하는 곳인지 이해할 수 있도록 했습니다.
- **시각적 위계** — 사용자의 행동을 바꾸지 않는 정보는 덜어내고, 남은 정보는 중요도에 따라 크기·간격·색상으로 강조했습니다
- **글자 길이 제한** — 서비스와 데이터의 특성을 기준으로, 화면에 보일 글자 길이와 입력 폼의 글자 수 제한을 정했습니다

→ [자세히 보기](docs/ai/design.md)

### 개발

- **구현** — 미리 만들어 둔 베스트 프랙티스를 기반으로, AI와 쉽고 빠르게 만들었습니다
- **정적 분석** — 타입 검사·ESLint·stylelint를 도입해, 기계가 잡을 수 있는 실수는 사람 리뷰까지 오지 않게 됐습니다
- **테스트** — 사용자가 보는 행동을 테스트해, 리팩토링한 뒤에도 AI·사람 리뷰보다 적은 비용으로 검증할 수 있었습니다
- **AI 코드리뷰** — 베스트 프랙티스와 공식 문서를 여러 AI 리뷰어에게 분야별로 나눠 맡겨서, 분야마다 기준에 근거한 지적을 받을 수 있었습니다

→ [자세히 보기](docs/ai/implementation.md)

## 레포 구조

웹과 앞으로 만들 앱이 같은 코드(공부 기록 타입, 날짜 계산 등)를 함께 쓸 수 있도록, 공용 코드를 따로 나눴습니다.

```
plan-for-myself
├── apps
│   ├── web          웹 서비스 (Next.js)
│   └── mobile       앱 (작업 예정)
└── packages
    └── shared       웹과 앱이 함께 쓰는 코드 — 공부 기록 타입·제한값, 날짜(공휴일·음력), 색 토큰
```

## 기여도

일정·기획, 디자인, 개발, QA, 배포를 혼자서 진행했습니다.

- **빌드·배포** — Turborepo, Yarn workspaces, Vercel
- **모니터링** — Sentry
